### Version Tracking 활용하기

- 개요: 예를 들어 소프트웨어 회사가 버전을 올렸는데 분명 거의 비슷하게 겹치는데 메모리 주소 등이 다 뒤집어져서 새로 분석하는건 머리 아플 것이다. 이때 유사도를 검사해서 차세대 버전에서 기본 버전에 쓰였던 함수, 자료형 등 각종 심볼과 디컴파일 된 결과를 철저히 분석해서 차기 버전 분석전에 미리 분석을 넣어 주는 스마트한 기능!

- 기드라의 Correlator(상관관계 분석기)가 처리하는데 성능이 괜찮은거 같다.
- 에러는 수동으로 고처야 함.
#### 사용 방법

- Source에는 분석이 끝난 파일을 Destination에서는 예를 들어 다른 플랫폼 용으로 만들어진 프로그램을 넣거나

- 혹은 버전이 올라가서 개발사에 의해  주소가 다 바뀐 업데이트 / 패치파일을 지정한다.

![[Pasted image 20260606220235.png]]

- 먼저 사전 체크를 반드시 하고 진행 한다 (거의 다 Pass이니 진행하겠다. )

![[Pasted image 20260606220842.png]]

- 검사가 끝나면 Version Tracking 세션이 열리고 해당 세션에서 두 파일을 비교 할 수 있다.

![[Pasted image 20260606221444.png]]


- 특히 왼쪽 상단에 일치할 가능성이 높은 함수와 자료형을 찾아 주기에 유용함.
- **Markup** = 함수가 아니라 함수 안의 **주석/라벨 등 세부 데이터 조각들의 매칭** 이라고 한다.
- **Implied** = 연쇄 추리로 알아낸 **신뢰도 높은 함수 간의 매칭** 라고 한다. 


#### 분석 데이터 실제로 병합하기 (관련 자료 그대로 가져옴)

1. **`Implied Matches`** 탭이나 **`Substance Matches`** 탭으로 이동합니다.
    
2. 기드라가 제안한 매칭 중에서 점수(Score)가 높고 확실한 함수들을 마우스로 드래그하거나 `Ctrl + A`로 **전체 선택**합니다.
    
3. 마우스 우클릭 후 `Accept Match` (매칭 수락)을 누릅니다. (상태가 녹색 체크 표시로 바뀝니다.)
    
4.  다시 마우스 우클릭 후 `Apply Markup Items` (마크업 아이템 적용)을 클릭합니다.
    
    - 이 버튼을 누르는 순간, 소스(A)에 있던 함수 이름, 주석, 라벨들이 데스티네이션(B) 파일의 함수 내부로 **실제로 복사되어 결합**됩니다.

## 추가로 Bsim 서버 구축하기 (이거 따라해도 안된다면 파일로하자...)


- 폴더 생성하기

```bash
sudo mkdir /DATA/Ghidra_SERVER_DATA/bsim_datadir

sudo chown -R 1001:1001 /DATA/Ghidra_SERVER_DATA/bsim_datadir

sudo chmod -R 775 /DATA/Ghidra_SERVER_DATA/bsim_datadir
```

- 컨테이너 시작 

```bash
docker run -d \
  --name bsim-server \
  --env MODE=bsim-server \
  -p 5432:5432 \
  -v /DATA/Ghidra_SERVER_DATA/bsim_datadir:/ghidra/bsim_datadir \
  3f23f672b9ff \ #ghidra_server 이미지 id
```

- 컨테이너 설정 

```bash

docker exec -it "도커 컨테이너" id /bash

/ghidra/support/bsim_ctl start /ghidra/bsim_datadir --auth trust

// postgresql 서버만 켜징

cd support

./bsim createdatabase postgresql://ghidra@localhost:5432/bsim_server medium_32

// bsim_server라는 database 생성 함.

```
