# 잘되던게 갑자기 안될까?

- 최근 필자는 도저히 감달이 되지 않는 Windows 10 을 저세상으로 밀어버리고 Pop OS! 24로 다시 갈아탔다. 
- 평소 ssh를 안전하게 쓰기 위해 중간에 `Wg-Easy`라는 컨테이너 방식의 VPN 사용해서 호스트에 접근하는데, 해당 컨테이너의 network 자체를 ufw에서 허용해야 클라이언트에서 접근가능 하였는데
- 우분투 ufw는 iptable을 제어하는 방식이겠거니하고 22.04 때랑 똑같은 방식으로 접근한게 화근이었다. 
- 계속 안돼서 `dmesg`를 털어서 알게 되었는데 `nftables`로 바뀐 바람에 그랬다. (10.8.0.2 (vpn client 주소) ->172.19.0.2 (Wg-easy Container의 네트워크상 IP ) -> docker host 172.18.0.1 ->host ssh 접근)이 안되게 되는것.
- iptables에서는 ipv6,ipv4 테이블이 다 다르고 통합 관리가 안되서 nftables로 우분투도 갈아탔다고 하니 업그레이드 하시는 분들은 방화벽 정책 조심하시길 바란다.
- UFW 왈 : 출발지가 172.19.0.2라고? 내 화이트리스트(허용 목록)에 이런 IP 대역은 없는데, 너차단. (172.18.0.0/16 에서 오는 기존 방식으로 )

- UFW의 무한 차단 로그

```bash
sudo dmesg -w | grep "UFW BLOCK"
```

```bash
[ 2023.921347] [UFW BLOCK] IN=br-644c6837213f OUT= PHYSIN=veth996cc2a MAC=ce:72:09:24:cf:10:06:c8:2c:97:d3:2c:08:00 SRC=172.19.0.2 DST=172.18.0.1 LEN=60 TOS=0x10 PREC=0x00 TTL=63 ID=48076 DF PROTO=TCP SPT=35134 DPT=22 WINDOW=65535 RES=0x00 SYN URGP=0 
```


```bash
sudo ufw allow in on br-644c6837213f # Wg-easy의 docker network
```
